# 技能与规范文档编写：强制前置覆盖矩阵

> TL;DR：动 SKILL.md 正文之前，先把源材料逐条抄进一张 6 列覆盖矩阵并打印成交付物第一节（SA-R1）；源材料每条必入表（SA-R4）、禁止空处置（SA-R5）、"不改"必须给理由（SA-R6）。矩阵是强制可见产物，本技能不含解析器。
> 适用范围：SKILL.md、技能文件、给 LLM 读的规范与自查清单的**新增与修订**。不适用：纯阅读技能、给人类看的报告。
> 依赖：矩阵各列的判定口径引用 `llm-doc-writing-standard`（R1 触发词、R6 三要素、R11–R13 清单闭环、R14 症状反查）；该技能不可用时按本技能 SA-R8/SA-R9/SA-R10 内嵌口径执行。

本文节序：症状速查 → 规则正文（SA-R1～SA-R11）→ 覆盖矩阵模板与三条机械校验 → 真实样例 → 编写流程 → 交付前自查清单。

## 规则正文

**SA-R1 动正文之前先输出覆盖矩阵。** 做法：任何对 SKILL.md / 技能 / 规范 / 清单正文的写入动作（edit、write、脚本改写）之前，先把覆盖矩阵作为交付物的第一节完整打印出来；矩阵未打印即视为本任务未开始。适用条件：任务包含"新增或修改技能正文"任一动作。违反后果：矩阵后置或省略时，漏项在写完正文后才被发现，返工成本翻倍；本规则是本技能其余规则的前置。

**SA-R2 矩阵列固定六列，列含义全行一致。** 做法：表头固定为 `源材料条目（原文摘录） | 落点规则编号 | 症状表是否新增 | 清单项 | description 触发词 | 处置（新增/合并/不改）`，六列顺序与列名不得增删改；每个单元格只放一个信息。适用条件：每次绘制矩阵时。违反后果：列名漂移使不同任务的矩阵无法机械比对，评审者无法一眼看漏项。

**SA-R3 源材料条目必须原文摘录。** 做法：第一列抄源材料的原句或报错原文，含可 grep 的字面串（如「未对文件…进行数字签名」），禁止概括成"签名问题"这类主题词；摘录过长时截取含关键串的一段并保留引号。适用条件：源材料为报错日志、用户口述、既有文档片段时。违反后果：概括后的条目无法与源材料逐条对齐，漏项核对失去基准。

**SA-R4 机械校验一：源材料每条必入表。** 做法：动手前先清点源材料条目总数 N，矩阵行数必须等于 N，并在矩阵上方写明"源材料 N 条 / 矩阵 N 行"；一条源材料拆到多行时需在行内标 `(1/2)`、`(2/2)` 使计数可还原。适用条件：每次绘制矩阵时。违反后果：计数对不上即存在漏项，而漏项正是本技能要消灭的故障。

**SA-R5 机械校验二：禁止空处置。** 做法：第三、六列必须填写实值；不适用时写「否」「不适用」或「—」，禁止留空，禁止写「待补充」「TBD」「暂不」「以后再定」。适用条件：每次绘制矩阵时。违反后果：空处置把"还没想清楚"伪装成"已处理"，评审时看不出来。

**SA-R6 机械校验三："不改"必须给理由。** 做法：处置列为「不改」时，同行的落点规则编号或症状表列必须写明理由，格式为「不改：<规则编号> 已有该反查行」或「不改：与本次源材料无关，属 <主题>」；理由须指向可查的规则编号或事实。适用条件：处置为「不改」的每一行。违反后果：无理由的"不改"与漏项在评审时无法区分。

**SA-R7 落点规则编号必须真实。** 做法：第二列填已存在的规则编号（如 PS-R5），或显式写「新增 <前缀>-R<n>」并保证该编号在本次交付的正文里确实出现；编号前缀与被改技能既有序列一致。适用条件：每次绘制矩阵时。违反后果：指向不存在的编号时，矩阵看似闭合而正文仍是空的。

**SA-R8 症状表新增列必须与报错反查闭环一致。** 做法：填「是」时，同行的源材料原文必须成为正文症状速查表里的一行，并指向第二列的规则编号；填「否」时该报错串必须已能在既有症状表 grep 到。适用条件：源材料含报错串或可观察症状时。违反后果：症状表漏收报错串时，带报错回查的人必须通读全文（R14 失效）。

**SA-R9 清单项必须与落点规则一一对应。** 做法：第四列写的检查点必须以「是否……」动作化问句表述，且在正文自查清单中以〔<规则编号>〕锚点出现；一条规则至少一个检查点，清单末尾保留兜底项。适用条件：第二列为新增编号时必填，合并进既有规则时写"并入 <编号> 检查点"。违反后果：清单与规则脱节时，新规则在执行层面等同于不存在（R11 失效）。

**SA-R10 description 触发词列必须穷举三类入口词。** 做法：第五列按任务类型词、症状/报错词、工件类型词三类各列至少一个词，并保证这些词最终出现在被改技能的 frontmatter description 中（去重后追加）；本次未新增触发词时写「无新增」并说明既有词已覆盖。适用条件：矩阵中任一行为新增或合并时。违反后果：触发词缺项使技能在对应场景不被加载，规则写得再好也不会被读到（R1 失效）。

**SA-R11 矩阵是第一交付节，先于编辑动作。** 做法：矩阵以 Markdown 表直接打印在本次回复正文的最前部，表上方一行写明源材料来源与计数；打印后再执行写盘。适用条件：每次技能正文改动。违反后果：矩阵写在回复末尾时，评审者看到的是既成事实，无法在写盘前拦下漏项；第一版不写解析器，只做强制可见。

## 覆盖矩阵模板与三条机械校验

### 空模板（复制后逐行填充，六列不得增删）

| 源材料条目（原文摘录） | 落点规则编号 | 症状表是否新增 | 清单项 | description 触发词 | 处置（新增/合并/不改） |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

### 三条机械校验（每张矩阵交付前自跑一遍）

1. **条目数对齐**：源材料 N 条 → 矩阵 N 行，拆分行用 `(i/N)` 标注（SA-R4）。
2. **无空处置**：第三、六列无空单元格、无「待补充/TBD/暂不」（SA-R5）。
3. **「不改」有理由**：每一行「不改」都带指向规则编号或事实的理由（SA-R6）。

## 编写流程

1. 清点源材料：把报错日志、用户口述、既有文档片段逐条抄成清单，记录条数 N（SA-R3、SA-R4）。
2. 打印覆盖矩阵：按六列填满，作为本次回复第一节输出（SA-R1、SA-R2、SA-R11）。
3. 自跑三条机械校验：条目数、空处置、"不改"理由（SA-R4～SA-R6）。
4. 按矩阵落点改正文：新增/合并规则、症状表行、清单锚点、description 触发词四处同步（SA-R7～SA-R10）。
5. 交付前过本技能自查清单，任一条答"否"即回到对应规则改完再交付。

## 交付前自查清单

- [ ] 1. 是否在动正文之前就把覆盖矩阵打印成交付物第一节？〔SA-R1、SA-R11〕
- [ ] 2. 矩阵是否为固定六列、顺序与列名未改、每格只放一个信息？〔SA-R2〕
- [ ] 3. 第一列是否为源材料原文摘录、含可 grep 的字面串？〔SA-R3〕
- [ ] 4. 是否写明源材料条数 N，且矩阵行数与 N 相等（拆分行有 `(i/N)` 标注）？〔SA-R4〕
- [ ] 5. 第三、六列是否无空单元格、无「待补充/TBD/暂不」？〔SA-R5〕
- [ ] 6. 每一行「不改」是否都给了指向规则编号或事实的理由？〔SA-R6〕
- [ ] 7. 每个落点规则编号是否真实存在或已在本次正文中新增？〔SA-R7〕
- [ ] 8. 症状表列填「是」的报错串，是否都成为正文症状速查表的一行并指向该编号？〔SA-R8〕
- [ ] 9. 第四列的检查点是否都带〔编号〕锚点写进自查清单，且清单末尾有兜底项？〔SA-R9〕
- [ ] 10. description 触发词列是否覆盖任务类型、症状/报错、工件类型三类词，并已回填 frontmatter？〔SA-R10〕
- [ ] 11. 三条机械校验（条目数、空处置、"不改"理由）是否逐条自跑并全部通过？〔SA-R4、SA-R5、SA-R6〕
- [ ] 12. 兜底核对：逐条比对 SA-R1～SA-R11，任一规则未被以上检查点覆盖即补查。〔SA-R1～SA-R11〕
